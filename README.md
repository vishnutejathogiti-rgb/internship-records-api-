# Internship Records API

A beginner-friendly REST API built with **Node.js, Express, SQLite, and Zod**. It supports CRUD operations, input validation, filtering, sorting, pagination, and consistent error responses.

## Requirements

- Node.js 20 or newer
- npm

## Setup

```bash
git clone https://github.com/YOUR-USERNAME/internship-records-api.git
cd internship-records-api
npm install
cp .env.example .env
npm run seed
npm start
```

The server starts at `http://localhost:3000`. The SQLite database is created at `data/internships.db`. The app creates the table automatically when it starts.

On Windows PowerShell, use `Copy-Item .env.example .env` instead of `cp`.

To run in watch mode: `npm run dev`

To run validation tests: `npm test`

## Data model

| Field | Type | Required on create | Rules |
|---|---|---:|---|
| `id` | integer | No | Generated primary key |
| `title` | string | Yes | 2–120 characters |
| `company` | string | Yes | 2–120 characters |
| `location` | string | Yes | 2–120 characters |
| `mode` | string | Yes | `onsite`, `remote`, `hybrid` |
| `status` | string | No | `open`, `in_progress`, `completed`, `cancelled`; defaults to `open` |
| `start_date` | date string | Yes | Real date in `YYYY-MM-DD` format |
| `end_date` | date string/null | No | Must be on or after `start_date` |
| `stipend` | integer | No | Non-negative; defaults to `0` |
| `description` | string | No | Up to 2,000 characters |
| `application_url` | URL/null | No | Must be a valid URL |
| `created_at` | timestamp | No | Set by database |
| `updated_at` | timestamp | No | Set by database and refreshed on update |

The example companies and records are fictional.

## API endpoints

Base URL: `http://localhost:3000`

| Method | Endpoint | Purpose | Success status |
|---|---|---|---:|
| GET | `/api/health` | Health check | 200 |
| GET | `/api/internships` | List, filter, sort, paginate | 200 |
| GET | `/api/internships/:id` | Read one record | 200 |
| POST | `/api/internships` | Create a record | 201 |
| PUT | `/api/internships/:id` | Update supplied fields | 200 |
| DELETE | `/api/internships/:id` | Delete a record | 204 |

`PUT` accepts one or more valid fields and updates only the fields supplied. This is a practical partial-update behavior for this small assignment.

### Pagination, filtering, and sorting

- `page`: positive integer, default `1`
- `limit`: integer from `1` to `100`, default `10`
- `status`: optional status filter
- `sort`: `created_at`, `start_date`, `title`, or `company`
- `direction`: `asc` or `desc`, default `desc`

Example: `GET /api/internships?page=1&limit=2&status=open&sort=start_date&direction=asc`

## Response format

Successful single-record responses:

```json
{
  "success": true,
  "data": {
    "id": 1,
    "title": "Backend Developer Intern",
    "company": "BrightByte Labs",
    "location": "Hyderabad, India",
    "mode": "hybrid",
    "status": "open",
    "start_date": "2026-11-10",
    "end_date": "2027-02-10",
    "stipend": 12000,
    "description": "Build and test REST APIs with a mentor.",
    "application_url": "https://example.com/internships/backend",
    "created_at": "2026-10-21T00:00:00.000Z",
    "updated_at": "2026-10-21T00:00:00.000Z"
  }
}
```

Timestamps in the example above are illustrative; actual values are generated by SQLite.

List responses use the same envelope plus pagination metadata:

```json
{
  "success": true,
  "data": [],
  "pagination": {
    "page": 1,
    "limit": 10,
    "total": 5,
    "total_pages": 1,
    "has_next_page": false,
    "has_previous_page": false
  }
}
```

Errors use a consistent format:

```json
{
  "success": false,
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "Request body is invalid.",
    "details": [
      { "field": "title", "message": "String must contain at least 2 character(s)" }
    ]
  }
}
```

## API examples

### List records

```bash
curl "http://localhost:3000/api/internships?page=1&limit=2"
```

### Get one record

```bash
curl http://localhost:3000/api/internships/1
```

### Create a record

```bash
curl -X POST http://localhost:3000/api/internships \
  -H "Content-Type: application/json" \
  -d '{
    "title": "Software Intern",
    "company": "Demo Tech",
    "location": "Remote",
    "mode": "remote",
    "start_date": "2026-11-15",
    "end_date": "2027-02-15",
    "stipend": 10000,
    "description": "Assist with API development.",
    "application_url": "https://example.com/apply"
  }'
```

### Update a record

```bash
curl -X PUT http://localhost:3000/api/internships/1 \
  -H "Content-Type: application/json" \
  -d '{"status":"in_progress","stipend":14000}'
```

### Delete a record

```bash
curl -i -X DELETE http://localhost:3000/api/internships/1
```

### Try validation errors

```bash
curl -X POST http://localhost:3000/api/internships \
  -H "Content-Type: application/json" \
  -d '{"title":"x","company":"Demo Tech","location":"Remote","mode":"space","start_date":"2026-02-30"}'
```

## HTTP status codes

- `200 OK`: successful read or update
- `201 Created`: record created
- `204 No Content`: record deleted
- `400 Bad Request`: invalid JSON, query, ID, or body
- `404 Not Found`: record or route not found
- `500 Internal Server Error`: unexpected server error

## Notes

- SQL values use prepared statements.
- Sort columns and directions are allowlisted before being inserted into SQL.
- JSON request bodies are size-limited.
- Unknown fields are rejected instead of silently accepted.
- The database file is excluded from Git; the schema and repeatable seed data are included.
- This is an educational starter, not a production-hardened service. Authentication, rate limiting, and deployment-specific configuration are intentionally outside the task scope.
